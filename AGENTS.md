# AGENTS.md

This monorepo provides regular expressions for Twitch URLs - clips, videos, channels, and collections - published as packages for different languages.

The regexes and their test cases live in a single source of truth shared by every language package:

- `README.md` - each regex in a structured `### Name` block.
- `tests.json` - test cases as `[url, expectedGroups]` tuples, shared across packages.

## Setup

- Node.js 24+.
- pnpm (see `packageManager` in root `package.json`).
- VS Code: the `oxc.oxc-vscode` extension is recommended (`.vscode/extensions.json`); format-on-save is enabled.

Install dependencies with `pnpm i` from the repository root.

## Repository layout

- `README.md` - source of truth for regexes. Each `### Name` block MUST contain, in order: heading, regex101 URL on its own line, `type FooGroups = { ... };` on its own line, and a `regex` code block with the pattern.
- `tests.json` - source of truth for test cases.
- `scripts/` - generator scripts that consume `README.md` and emit per-language source files. Do not duplicate the regex source in language packages.
- `packages/` - one directory per language package.

## Commands

- `pnpm build` - run the generator; regenerate all source files for every language package from `README.md`.
- `pnpm lint` - run `oxlint` across the repo.
- `pnpm lint:fix` - run `oxlint --fix` across the repo.
- `pnpm fmt` - run `oxfmt` and format supported files in place.
- `pnpm fmt:check` - run `oxfmt --check` to verify formatting without writing.

The root `package.json` should have scripts to run `build` and `test` scripts in every language package.
Each script should have a language suffix.

- `pnpm build:ts` - TypeScript: build project (CJS + ESM + `.d.ts` via `tsdown`).
- `pnpm test:ts` - TypeScript: run unit tests.
- `pnpm test:ts:watch` - TypeScript: run unit tests in watch mode.

## Tests

Tests are written using built-in test runners for every language.
Tests should read `tests.json` and, for each regex, assert:

- Positive: each URL in the category matches `*_REGEX_EXACT` and yields the expected groups.
- Negative: URLs from other categories do NOT match `*_REGEX_EXACT`.

## Authoring workflow

1. Edit regexes only in `README.md`, inside the `### Name` block. Keep the heading, regex101 URL, `type` line, and ` ```regex ` block in that order.
2. Add or update positive cases in `tests.json` under the matching category.
3. Run the language package's generator/build to regenerate its source files.
4. Run the language package's tests.
5. Run `pnpm lint` and `pnpm fmt:check` at the repo root.

The H1 paragraph in `README.md` is the canonical package description and is auto-injected into each language package's files by `scripts/build.ts`.

## Code style

- 2-space indent, single quotes, LF line endings, UTF-8, trailing newline.
- `oxfmt` for formatting, `oxlint` for linting. `tests.json` is excluded from `oxfmt` (`.oxfmtrc.json`).
- ESM only (`"type": "module"`); no default exports in generated code.

## Regex contract

- Flavor: JavaScript.
- `*_REGEX_STRING` constants MUST NOT include `^` or `$`; consumers add anchors themselves.
- `*_REGEX_EXACT` is the anchored form with `^` and `$`.
- Named capture groups declared in the `type` line MUST match the groups in the regex.

## Do / Don't

- Do edit `README.md` and `tests.json` as the canonical sources.
- Do run the generator and tests after any change to the canonical sources.
- Do preserve the `// generated` header in generated files; it marks them as build output that must be regenerated, not hand-edited.
- Don't hand-edit generated files (e.g. `packages/typescript/src/index.ts`).
- Don't duplicate regex source into per-language files.
- Don't add root-level dependencies unless they are used by `scripts/` or root-level tooling.

## TypeScript

Package: `packages/typescript/`, published as `twitch-regex` on npm.

- `src/index.ts` - generated by `scripts/build.ts`. Do NOT hand-edit.
- `src/index.test.ts` - `node --test` suite. Imports `tests.json` from the repo root.
